# Piledriver

Bug hunting workflow using TLA+ formal methods. Works with Claude Code.

- **piledriver** (Python CLI) - For agents. Scaffolds sessions, validates phase transitions, runs TLC.
- **pilemonkey** (Go TUI) - For humans. Watch file changes and session progress in real-time.

## Install

```bash
./install.sh
```

Requires `~/.claude` to exist (Claude Code must be installed).

## Usage

From any project directory:

```
/piledriver I think there's a race condition in the session manager
```

Or use the CLI directly:

```bash
piledriver init <session-name>              # Create session with scaffolding
piledriver set-phase <session> <phase>      # Transition between phases
piledriver bug <session-name> <bug-name>    # Create bug reproducer
piledriver test <session-name> [bug-name]   # Run reproducer validation
piledriver check <session-name> [--sany]    # Run TLC model checker
piledriver pr <session-name>                # Generate PR draft
piledriver status [session-name]            # Show session state
```

Each command outputs guidance on next steps.

## What it does

1. **Reconnaissance** (optional) - Cast a wide net with race detectors, static analyzers, pattern grep
2. **Scoping** - Define what's formally modeled vs assumed correct
3. **Assumptions** - Document what you assume about components outside the model
4. **Verification** - Choose technique (TLA+, property testing, fuzzing, etc.) and verify
5. **Report** - Document findings, create reproducers that fail before fix, pass after

## Directory structure

Created in your project's working directory:

```
.piledriver/
└── <session>/
    ├── state.json         # Phase tracking (used by CLI and pilemonkey)
    ├── reconnaissance.md  # Automated analysis results (optional)
    ├── boundary.md        # What's in/out of the model
    ├── assumptions.md     # Assumptions about "outside"
    ├── model.tla          # TLA+ specification (or other verification artifact)
    ├── model.cfg          # TLC configuration
    ├── probe.md           # Real-world testing plan
    ├── pr-draft.md        # Generated by `piledriver pr`
    └── reproducers/
        └── <bug>/
            ├── README.md
            ├── run.sh       # Runs tests on base and fix commits
            └── results.json # Generated by run.sh
```

## Pilemonkey TUI

Run in a second terminal to watch the agent work:

```bash
cd pilemonkey && go build && ./pilemonkey -s <session-name>
```

Shows phase progress, file changes, TLC results, and lets you add notes.

## Shell Completion

### Bash

```bash
# Add to ~/.bashrc
source /path/to/piledriver/completions/piledriver.bash

# Or copy to system completions
sudo cp completions/piledriver.bash /etc/bash_completion.d/piledriver
```

### Zsh

```bash
# Copy to a directory in your $fpath
mkdir -p ~/.zsh/completions
cp completions/_piledriver ~/.zsh/completions/

# Add to ~/.zshrc (before compinit)
fpath=(~/.zsh/completions $fpath)
autoload -Uz compinit && compinit
```

### Fish

```bash
# Copy to fish completions directory
cp completions/piledriver.fish ~/.config/fish/completions/
```

## Requirements

- Python 3
- Java (JRE 11+) or Nix
- Claude Code

The installer downloads `tla2tools.jar` automatically.

## Reproducer contract

Each `run.sh` must:
1. Checkout base commit, run tests (expect failures)
2. Checkout fix commit, run tests (expect pass)
3. Write `results.json`:

```json
{
  "base_commit": "abc123",
  "fix_commit": "def456",
  "base_result": {"total": 5, "passed": 2, "failed": 3},
  "fix_result": {"total": 5, "passed": 5, "failed": 0},
  "success": true
}
```

Success = base has failures AND fix has none.
